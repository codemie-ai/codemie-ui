## Backend contract (REAL, replaces A1-A6)
Everything exists only when backend flag `WORKFLOW_CONTRACT_LINKING_ENABLED` is true (default false). With it off: no contract warnings, no `coverage` key, no `warnings_truncated` key -> UI must handle absence of all of them.

- A1 CONFIRMED: `error_type: "contract_validation"` (`src/codemie/workflows/constants.py:28`).
- A2 WRONG: no `severity`, no `strict`. Severity is `outcome`: `"ERROR" | "WARNING" | "UNVERIFIED"` (UPPERCASE) (`validation/contract_issues.py:59-63`, `validation/models.py:74`). Errors always carry `outcome:"ERROR"` and appear only in `error.details.errors[]`. There is no "missing severity means error" logic.
- A3 WRONG: coverage = `{validated_states:int, total_states:int, uncovered_state_ids:string[], analysed:bool, cap_reached:bool}` (`contract_issues.py:324-341`). No `checked`/`total`/`unverified`: derive the unverified count by counting `outcome === "UNVERIFIED"` in `warnings`. Show a "not analysed" state when `analysed` is false.
- A4 PARTIAL: contract warnings ARE in the 2xx body `warnings[]` but `kind` is `"contract_validation"` (not `"contract"`) (`contract_issues.py:110`). Create (`routers/workflow.py:494-500`) and update (`:635-641`) return `{message, data, warnings, coverage?, warnings_truncated?}`. `warnings[]` mixes kinds in this order: `consumer_slot`, `tool_access_owner_integration`, `contract_validation` (`service/workflow/save_validation.py:124-132`). UNVERIFIED notices are in the same `warnings[]` with `outcome:"UNVERIFIED"`, `kind:"contract_validation"` (no separate field). Clean workflow: `warnings:[]` plus `coverage`. `warnings[]` capped at 100 contract entries; `warnings_truncated:N` appears only when cut.
  - Rejection = HTTP 400; with `error_format=json` the body is `{"error":{"message":"Workflow Configuration error","help":"","details":{error_type:"contract_validation", message:"Workflow contracts are not satisfied", errors:[...], warnings:[...], coverage:{...}, warnings_truncated?}}}`. Without `error_format=json`, details is a `<br>` string -> ALWAYS pass `error_format=json`. Warnings inside a rejection are contract-only (no consumer_slot/tool_access). Error entries have no `kind`; warning entries do.
- A5 PARTIAL: validate-before-save = `POST /v1/workflows/validate?error_format=json` (`routers/workflow.py:530-570`). Body `ValidateNewWorkflowRequest` (`core/workflow_models/workflow_models.py:463-475`): `project` REQUIRED; `name`, `description` optional; `mode`, `yaml_config`, `assistants`, `tools`, `states`, `supervisor_prompt`, `meta_config` accepted. Needs project membership only, persists nothing, autonomous mode returns 410. Response `{message:"Workflow configuration is valid", warnings[], coverage?, warnings_truncated?}`; 400 with same rejection envelope. Also returns consumer_slot and tool_access warnings. Guarantee covers contract validation only (not category/guardrail/access checks). Not for per-keystroke use.
  - `POST /v1/workflows/{id}/validate` (`:666-709`) returns the same shape incl. contract warnings, `outcome`, `coverage`; needs write access, takes full `UpdateWorkflowRequest` body, supports `error_format`.
  - Restore: backend rollback `POST /workflows/{id}/versions/rollback` returns plain `BaseResponse` and validates with `link_contracts=False` (`service/workflow/workflow_version_service.py:94-103`) -> NO contract warnings.
