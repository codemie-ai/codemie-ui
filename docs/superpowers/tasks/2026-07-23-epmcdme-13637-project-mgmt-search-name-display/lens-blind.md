- **`ProjectSettings.tsx` and `UserSettings.tsx` missing debounce** (`src/pages/integrations/components/ProjectSettings/ProjectSettings.tsx`, `UserSettings.tsx`): Every other filter page (`DataSourceFilters`, `FavoritesAllFilters`, `SkillsFilters`, `WorkflowsFilters`, `AssistantFilters`) received the `useDebouncedApply` + `handleProjectFilter` treatment, but these two pages still pass `onFilter: loadProjectOptions` directly, firing an API call on every keystroke.

- **`isLoadingProjects` stuck on API error** (all `applyProjectSearch` callsites): `setIsLoadingProjects(false)` is only called via `await loadProjectOptions(...)` completing. If `useProjectOptions`'s internal catch is ever removed or the error is rethrown, the loading spinner never clears. A `finally` block in `applyProjectSearch` would make this resilient.

- **Empty-string passed as `name` when `assistant?.project` or `skill.project` is `undefined`** (`AssistantDetailsSidebarSections.tsx` line ~459, `SkillDetails.tsx` line ~286): `assistant?.project ?? ''` passes `''` to `ProjectNameDisplay`, which renders an empty React fragment — visually the same, but `DetailsProperty` may differ from the previous `undefined` value in terms of rendering an empty property row vs. nothing.

- **Inconsistent `|| undefined` guard across `ProjectNameDisplay` call sites**: `AssistantDetailsSidebarSections` and `SkillDetails` use `projectDisplayName || undefined` (converting empty string to `undefined`) while `DataSourceDetails` passes raw `projectDisplayName` without the guard. The trimming inside `ProjectNameDisplay` absorbs the difference, but this inconsistency signals unclear ownership of the empty-string contract.

- **Potential double initial load via `useDebouncedApply` and explicit `useEffect`** (`DataSourceFilters`, `FavoritesAllFilters`, `SkillsFilters`, `WorkflowsFilters`): Each component both calls `loadProjectOptions()` in a `useEffect` on mount AND registers `useDebouncedApply(projectSearchTerm, 1000, applyProjectSearch)` with `projectSearchTerm` initialised to `''`. If `useDebouncedApply` fires for the initial value (which is common for such hooks), two requests fire on mount: one immediately and one after 1 s.

- **`renderProjectOption` exported from a hook file** (`src/hooks/useProjectOptions.ts`): A module-level render function that imports a React component is co-located with a hook for no cohesion reason. If the hook is ever code-split or tree-shaken, `renderProjectOption` (which imports `ProjectNameDisplay`) travels with it unnecessarily; a dedicated `projectOptionRenderer.tsx` utility file would be more appropriate.

- **`matchesProjectSearch` double-negation** (`src/utils/projectDisplayName.ts` line ~2092): `!!project.display_name?.trim().toLowerCase().includes(q)` — the `!!` converts `undefined` to `false` when `display_name` is null/undefined, which is correct, but it also double-negates a boolean returned by `.includes()`. The intent is non-obvious; `project.display_name?.trim().toLowerCase().includes(q) ?? false` makes the null-coalescing explicit.

- **`truncate` prop silently ignored when `displayName` is absent** (`src/components/ProjectNameDisplay/ProjectNameDisplay.tsx`): The component early-returns `<>{name}</>` when `trimmed` is falsy, silently discarding `truncate`. A consumer that passes `truncate` to try to clip a long technical name (no display name available) gets no truncation and no warning. This is undocumented in the interface.

- **`filterBy` cast masks type errors** (`src/components/Filters/Filters.tsx` line ~9): `definition.config?.filterBy as string | undefined` — if `definition.config` is typed to disallow `filterBy` or gives it a different type, the cast will suppress the TypeScript error and pass incorrect data silently to PrimeReact.

- **Removed JSDoc not replaced on new component** (`src/components/ProjectNameDisplay/ProjectNameDisplay.tsx`): The `ProjectNameCell` JSDoc described the Super-Admin lazy-fetch behavior. It was deleted and not migrated to `ProjectNameDisplay`, which is now the canonical display component. Future maintainers lose the context that resolution differs for Super Admins viewing unassigned projects.
