Clearing-on-model-change implementation: Each file tracks `previousModelRef` (a `useRef` seeded with the initial `selectedModel`) alongside `effortValueRef` (a ref kept in sync with the live effort value every render, read without being a hook dependency). Inside the existing `useEffect` keyed on `[selectedModel, trigger, setValue]` (now also calling `trigger('effort')`), the code only clears `effort` when `previousModelRef.current` is truthy AND differs from the current `selectedModel` AND the current effort value is not in the new model's `getEffortLevels(selectedModel)` list; the ref is then updated to the new `selectedModel` unconditionally. Because the ref starts equal to the mount-time `selectedModel`, the very first effect run always sees "no change" and never clears — so a legitimately-saved effort on an editing assistant, or a store that is still loading on first render, is never wiped on mount.

Notes:
- PrimeReact's `Dropdown` panel never reports a non-`display:none` computed style in jsdom (it always takes the "hidden measurement" branch in `DomHandler.absolutePosition`/`getHiddenElementDimensions` because jsdom has no layout, so `element.offsetParent` is always null, and that utility's final step always restores `display:none` after measuring). This makes `getByRole('option', ...)` fail even though the option `<li role="option">` elements are genuinely in the DOM — `getByRole` excludes elements RTL considers inaccessible (display:none), while `getByText`/`findByText` have no such visibility filter. I adjusted the Task-4 test's interaction (not its intent) to `await user.click(await screen.findByText('high'))` instead of `getByRole('option', {name: 'high'})`. Any future test clicking an Effort or other raw-`Dropdown` option should use `findByText`/`getByText` on the option label, not `getByRole('option', ...)`.
- Similarly, PrimeReact's `MultiSelect` (used by `LLMSelector`) renders an accessible `role="combobox"` hidden input with `pointer-events: none` (by design, for a11y-only exposure) — `userEvent.click` correctly refuses to click it directly. To drive the LLM model selector interactively in a test, locate the combobox by role/name and then `.closest('.p-multiselect')` to get the actual clickable trigger: `screen.getByRole('combobox', { name: 'LLM model' }).closest('.p-multiselect')`.
- `useProjectLLMModels` only calls `appInfoStore.getProjectLLMModels(projectName)` when `appInfoStore.projectLlmModels[projectName]` is unset — it does not refetch on every mount when a project is already cached. Since many tests in this file share the project name `test-project`, a test that needs a specific, fresh model list for that project must reset `appInfoStore.projectLlmModels = {}` before rendering (done in the new model-switching test) or it will silently reuse an earlier test's cached model list. This is pre-existing behavior, not something I changed — worth knowing for Task 7/8/9 if they add more tests that mock `v1/llm_models` for project-scoped forms.
- Guidance text `"Set only the parameter your model supports."` and the warning text are rendered via plain `<p>` and the existing `InfoWarning` component (`type={InfoWarningType.WARNING}`) respectively — same component already used by `LLMSelector`'s "invalid model" note, so styling is consistent with existing warning surfaces in the codebase.
